# 事故处理与回滚流程

---

## 事故分级

| 级别 | 定义 | 响应时间 |
|------|------|---------|
| P0 | 服务不可用、数据丢失 | 立即 |
| P1 | 功能损坏、核心流程中断 | < 1h |
| P2 | 非核心问题、workaround 存在 | < 4h |
| P3 | 轻微问题、不影响业务 | < 24h |

---

## 通用流程

1. **识别** — 发现问题
2. **止损** — 停止扩散（kill 进程 / 回滚代码 / 切通道）
3. **评估** — 影响范围 + 是否可逆
4. **回滚** — 优先回滚到上一个稳定版本
5. **复盘** — 记录根因 + 预防措施

---

## 回滚操作

```bash
# 代码回滚
cd ~/srv/xi && git log --oneline -5  # 找上一个稳定 commit
git revert <commit>  # 安全回滚，不丢历史

# 服务重启
kill <pid> && cd ~/Documents/Github/<project> && pnpm dev
```

---

## Ask First（P0/P1）

- 生产环境改动
- 删数据、删文件
- 改 secrets / token
- 花钱/下单操作

---

## 预防原则

- 改前备份
- 小步提交
- 可逆 > 不可逆
- 不在深夜/周末做高风险操作
