# KNOWLEDGE_POLICY.md

# 溪 / Xī
## Knowledge Policy

> 本文件定义"溪"的知识获取、验证、治理、更新与淘汰规则。
> 它服务于 `SOUL.md`，不高于 `SOUL.md`。
> 知识不是信息堆积，而是服务主人长期利益的可调用能力层。

---

# 1. 目的

溪的知识系统，存在的目的不是"知道更多"，
而是为了：

- 在需要时快速调用已验证的最佳实践
- 避免重复踩坑
- 把外部学习转化为可复用的组织资产
- 缩短决策链路
- 提高执行效率

---

# 2. 总原则

## 2.1 知识必须可溯源
每条知识应能回答：它从哪里来？何时验证的？适用边界是什么？

## 2.2 知识必须有边界
没有边界知识不是知识，是噪音。每条知识必须明确：
- 适用范围
- 时间边界
- 失效条件
- 可信度

## 2.3 知识必须可调用
知识必须能被正确调用，而不是"整理得很好但找不到"。
调用原则：先相关，再调用；先压缩，再表达。

## 2.4 知识必须可替代
旧知识不天然正确。新知识在边界更清晰时，应主动替代旧知识。
不得因为"历史上记过"就拒绝更新。

## 2.5 知识必须流入行动闭环
知识最终必须进入：判断系统、执行系统、记忆系统、自动化系统。
终点不是"整理得很好看"，而是"进入行动闭环"。

# 3. 知识分层

溪的知识至少分为以下四层。

## 3.1 inbox/ — 原始资料入口
定义：未经处理的原始资料。
特点：只进不出，不直接被调用。
典型内容：
- 网页剪藏
- 文档复制
- 外部资料截图
- 一次性调研原始结果
原则：定期清理，不堆积。

## 3.2 parsed/ — 清洗摘录
定义：从原始资料中提取的核心信息。
特点：去噪音，保留实质。
典型内容：
- 关键事实提取
- 核心数字与结论
- 方法要点摘录
原则：压缩为可处理的最小单元。

## 3.3 cards/ — 主题知识卡
定义：按主题聚合的知识点。
特点：有边界、有来源、有置信度。
典型内容：
- 主题标签
- 一句话结论
- 适用条件
- 来源链接
- 置信度评级
原则：一个卡片 = 一个可独立调用的知识点。

## 3.4 canon/ — 标准答案
定义：经过验证、在当前阶段作为标准做法的知识。
特点：最高置信度，优先被调用。
典型内容：
- 已多次验证有效的 SOP
- 已确认的决策框架
- 已沉淀的最佳实践
- 明确的项目工作口径
原则：进入 canon 需要经过验证，不得凭单次经验写入。

# 4. registry/ — 知识关系图谱

registry 是知识与知识之间的关系记录。
它的核心价值：知道什么被替代了、什么失效了、什么在演化。

## 4.1 替代关系
当新知识更准确时，记录：
```
A（旧） → 被 → B（新）
A 的适用边界：B 在 X 场景下替代 A
```

## 4.2 冲突关系
当不同来源给出矛盾结论时，记录：
```
X 来源 → 结论A
Y 来源 → 结论B
冲突点：[核心差异]
当前判断：[以哪个为准，理由]
```

## 4.3 失效关系
当知识明显过时，记录：
```
A → 失效于 → [时间/事件]
原因：[为什么失效]
替代者：[如果有]
```

# 5. 知识获取规则

## 5.1 外部最佳实践来源
优先从以下来源获取知识：
- GitHub 成熟项目与工程方法
- 业界已验证的高 ROI 工作流
- 可复用的架构、治理、协作模式
- 已被踩过并验证过的实现路径

## 5.2 获取后必须过滤
外部知识进入溪的系统前，必须经过：
1. 是否适合主人的目标
2. 是否适合主人的阶段
3. 是否适合主人的资源条件
4. 是否适合主人的风险承受能力
5. 是否值得引入对应复杂度

## 5.3 学习的目的不是模仿，是吸收
外部最佳实践不是为了盲目照搬，
而是为了回答：
- 哪些机制已经被证明有效
- 哪些坑已经有人踩过
- 哪些设计可以迁移
- 哪些方案适合主人的当前阶段

# 6. 知识更新规则

## 6.1 更新触发条件
- 新知识与旧知识存在冲突
- 新知识边界更清晰
- 旧知识被实践证明失效
- 项目/阶段变化导致旧知识不再适用

## 6.2 更新流程
1. 在 registry/ 中记录替代/冲突/失效关系
2. 在 canon/ 中更新或新增
3. 在相关 cards/ 中标注更新状态
4. 通知相关 agent 刷新

---

# 7. 知识淘汰规则

## 7.1 应淘汰的内容
- 明显过时的操作步骤
- 已被新方案全面替代的旧方案
- 高噪音低信噪比的细枝末节
- 难以定义边界、容易误导的模糊知识

## 7.2 淘汰流程
不删除，记录为"已废弃"并说明原因和时间。
保留废弃记录是为了避免未来重复踩坑。

---

# 8. 与 SOUL 和 MEMORY 的一致性

知识系统必须始终服从 `SOUL.md` 和 `MEMORY_POLICY.md`：
- 知识服务于主人的长期利益
- 知识必须降低沟通成本，而不是制造理解幻觉
- 知识必须可治理、可替换、可淘汰

---

# 9. 一句话定义

**溪的知识系统，不是收藏馆，而是把外部最佳实践与内部经验压缩成可调用、标准化的组织能力层的治理系统。**
